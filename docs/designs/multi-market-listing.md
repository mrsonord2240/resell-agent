## Problem Statement

Sam resells on eBay and Depop and wants Poshmark too. Today resell-agent turns a photo into a priced draft and publishes to eBay end to end, but:
- eBay posting needs hosted HTTPS image URLs pasted in by hand (`validateHttpsImageUrls` in `src/publish.ts`).
- Depop and Poshmark cannot post at all. `src/browser-automation.ts` is a generic shell driven by one env JSON of CSS selectors (title, description, price, photos, publish button). No selectors are configured, and those four fields can't complete either site's sell form anyway.
- One item at a time. There is no batch from a pile of photos.

Paid crosslisters (Vendoo, List Perfectly, Crosslist, Listelf at $10 to $50 a month) cover this, but Sam would rather build it free and tailor it.

## What Makes This Cool

"Snap a pile, live everywhere": photograph a rack tonight and wake up to every piece drafted, priced from comps and live on eBay, all unattended. Then sit down for one posting session in which every Depop and Poshmark form opens already filled: one click per market when every field mapped, with any unmapped field highlighted. Unlike the paid tools, the AI does the work: it reads the photo, writes the listing and prices it. Those tools make you type it all.

Sam wants all four directions eventually, in this order:
1. Snap a pile, live everywhere (this design).
2. Sold once, gone everywhere (delist sync).
3. Hands-off shop (Poshmark sharing, price drops on stale listings, offers to likers).
4. Phone-first (the deferred Android app).

## Constraints

- Free. No paid crosslister or paid API.
- Local. Runs on Sam's Windows machine (desktop Electron app plus CLI) with his own logged-in marketplace accounts.
- Personal volume, one seller.
- Poshmark's community guidelines ban "unauthorized programs or other forms of automation", and Poshmark has cracked down on mass listing removals ([listperfectly](https://listperfectly.com/selling/poshmark-in-2026-policies-enforcement/), [valueaddedresource](https://www.valueaddedresource.net/poshmark-cracks-down-on-listing-removals/)).
- Depop's 2026 terms acknowledge third-party crosslisting tools. Depop has an invite-only Partner Selling API with OAuth, listings, orders and webhooks ([partnerapi.depop.com](https://partnerapi.depop.com/api-docs/)).

## Premises (agreed 2026-11-26)

1. The first cut is Snap a pile: photos become drafts, then eBay posts via API and Depop and Poshmark post via browser. Features 2 to 4 come later, but nothing in this cut may block them.
2. Free and local. No paid tools; Sam's own accounts.
3. On Depop and Poshmark the tool fills the sell form in a dedicated browser profile that Sam signs into once by hand (not his everyday Chrome profile), and Sam clicks the final Post. A human click reduces, but does not remove, the guessing about whether a post landed; the wait contract below covers the rest. On ban risk: form filling is still automation under Poshmark's guideline. No evidence shows Poshmark treats a human final click differently, so Poshmark use is an accepted residual risk Sam chooses to take (2026-11-26 review), with the halt rules below. Depop's terms accept crosslisting tools, so its risk is lower.
4. The selector-config approach can't fill a real form, which also needs category, size, brand, condition and shipping. Each site gets its own script, written as code.
5. Sam emails developers@depop.com for Partner API access in parallel. If granted, Depop moves to an API adapter like eBay.

Landscape note (eureka, logged): crosslisters assume full automation. For one low-volume seller, filling the form and having a human click Post is a low-volume, human-in-the-loop pattern. It is not proven safer under Poshmark's rules (see Premise 3's accepted risk), and it reduces publish-verification guessing rather than removing it (see the wait contract).

## Approaches Considered

### Approach A: Assisted fill (chosen)
Per-site Playwright scripts run in a persistent, logged-in browser profile. They fill every sell-form field, then stop for Sam to click Post. The tool watches for the post-success URL and records the listing URL. Batch mode opens one tab per item. Effort M, risk medium. Reuses `publish.ts`, `draft-file.ts` and the browser shell.

### Approach B: Adapters + inventory ledger
A plus a local inventory ledger across markets. Ruled out for now as the slowest path to a first Depop post. Its ledger is the base for delist sync; A keeps the seam open for it.

### Approach C: Chrome extension
A "Fill from resell-agent" button on the sell pages, pulling drafts from the local app. No bot fingerprint. Ruled out for now: a new surface to build, and no unattended batch. It stays the fallback if Playwright logins get blocked.

## Recommended Approach

Approach A, built behind a small marketplace-adapter seam so the ledger (B) and delist sync drop in later.

Shape:
```
  batch/ (one subfolder per item; this cut does not group a flat pile)
        |
        v
  intake: 1 subfolder = 1 item
        |
        v
  brain: vision -> comps -> price -> per-market listing copy   (existing pipeline.ts)
        |
        v
  DraftFile per item  (draft-file.ts; gains per-market fields: category, size, brand, condition, shipping)
        |
        +--> eBay adapter      : Media API photo upload -> inventory -> offer -> publish (no URL pasting)
        +--> Depop adapter     : open sell form in saved profile -> fill all fields -> WAIT for Sam's Post -> capture URL
        +--> Poshmark adapter  : same as Depop
        |
        v
  publishResults merged per market (mergePublishResults), status shown in the GUI and `resell status`
```

Adapter seam, a minimum to keep later work open: `{ post(draft): Result; status?(id); delist?(id) }`. Only `post` is implemented now.

### Assisted-fill contract

**Browser identity.** The default is a dedicated persistent Playwright profile (`BROWSER_AUTOMATION_PROFILE_DIR`, one per market). Sam signs into it by hand once. The fallback, if the site blocks Playwright's Chromium at login, is to attach over CDP to a real Chrome launched with its own dedicated user-data-dir. Neither one is Sam's everyday Chrome profile. If both fail, switch to Approach C.

**Runner.** A single batch-runner module owns one long-lived browser context per market for the whole session. It opens one tab per item in that context, fills it, and leaves it open while Sam clicks. It writes each draft's result as its tab resolves. Both the CLI (`resell post-batch <dir>`) and the GUI server (inside Electron's main process) call the same module. A lock on the profile directory allows one runner at a time.

**What changes in `src/browser-automation.ts`.**
- Kept: the Playwright loading, the URL host checks and the success-URL check.
- Replaced: the per-call launch and close (by the runner's shared context) and the tool-side `publishSelector` click (removed; Sam clicks).
- Replaced: the `publishClicked` error classification, by human-submit detection. The runner watches the tab for the site's listing-create request or a navigation off the sell form.
- Assisted fill always runs headful.
- The `*_BROWSER_FLOW` env JSON and the `ENABLE_BROWSER_AUTOMATION` gate are dropped; per-site scripts in code replace them.

**Wait lifecycle and recorded states.** There is no timeout while the runner is alive: a filled tab waits for Sam. The pitch's overnight part is the unattended draft and eBay step; Depop and Poshmark fills happen when Sam starts a posting session.

| State | Meaning | Re-run rule |
|---|---|---|
| `filling` | Written to the item's `draft.json` before the tab is filled (the durable pre-wait marker) | A re-run that finds `filling` with no live runner holding the profile lock treats it as `unknown` |
| `published` + URL | Submit seen and listing URL captured | Never re-filled |
| `unknown` (verify first) | Submit seen but URL not captured, or a stale `filling` | Skipped by re-runs until Sam confirms it in `resell status` or the GUI (mark posted with a URL, or mark not posted) |
| `not_posted` | Sam closed the tab with no submit seen | Re-filled on the next run unless he excludes the market |
| `skipped` | The existing meaning: not attempted this run (already published, or market excluded) | Unchanged |
| `error` | Failed before or during fill; no submit seen | Re-filled on the next run |

Any state in which Post may have been clicked resolves to `unknown`, so it is never re-filled automatically. Two code changes carry this: `publishDraftBundle` in `src/publish.ts` must skip a prior `unknown` as well as a prior `published`, and `mergePublishResults` must keep a prior `unknown` over a new `skipped`, as it already does for `published`.

**Poshmark halt rules.** The runner stops all Poshmark work and records the reason when it sees any of: a captcha or login challenge it didn't expect, a policy or warning notice, a removed listing, or an account restriction banner. After a halt, Poshmark falls back to manual listing (copying fields from the GUI) or to Approach C, and never to an automatic retry.

### Batch layout and status

- On disk: `batch/<item>/` holds that item's photos and its `draft.json` (a DraftFile). `batch/batch.json` indexes the items with each one's per-market status, rebuilt from the drafts.
- `resell status --batch <dir>` lists every item and market in a table and flags the `unknown` and unmapped-field rows. The GUI gets a batch view built from the same index.
- A re-run of `post-batch` resumes only the items and markets whose state allows it, per the table above.

Wireframe: none. UI work (the batch list and per-market post buttons in the existing GUI) is left to /plan-design-review on this doc.

## Open Questions

- Will Playwright's Chromium get past Depop's and Poshmark's logins? Mitigation: sign in once by hand in the persistent profile, or attach to Sam's real Chrome over CDP with a dedicated user-data-dir. If both fail, switch to Approach C.
- Flat-pile grouping by vision is later work. This cut needs one subfolder per item.
- Per-market category and size mapping: our attributes are free text, but the Depop and Poshmark pickers are fixed trees. They need a mapping step, model-assisted with a fallback that leaves the field for Sam.
- Poshmark "sold elsewhere": when delist sync arrives, mark items not-for-sale instead of deleting them, given the removal crackdown.

## Success Criteria

- From a batch folder of 10 item subfolders, one command or GUI action produces 10 drafts and publishes all 10 to eBay with no URL pasting.
- In the posting session, each Depop and Poshmark form opens filled. An item takes one click per market when every field mapped. Any field the tool couldn't map is highlighted in the tab and listed in `resell status --batch` and the GUI, so Sam knows exactly what still needs him.
- Every post's URL and state is recorded per market and visible in `resell status --batch` and the GUI.
- Re-running never re-fills a market whose state is `published` or `unknown` (see the contract table).

## Distribution Plan

Personal use. It ships through the existing desktop app (`desktop/`, Electron) and the `resell` CLI on Sam's machine. No packaging or CI change is needed for this cut.

### Findings by section

- **S1 Architecture.** The runner, adapters and CLI shape hold up. CRITICAL GAP: there is no way to resolve `unknown` (D3, now fixed). The GUI server runs in Electron's main process, so it can host the runner. The per-market profile lock stops the CLI and the GUI from running Depop at the same time.
- **S2 Errors.**
  - A Depop field not found records `error` with the field name.
  - An expired login (redirect to sign-in) halts that market with "sign in again" and doesn't retry.
  - A photo upload rejected by the form records `error`.
  - If the mapping model returns malformed or invalid JSON, every field it was meant to fill is left unmapped and flagged; the draft does not fail.
  - A Media API 401 or scope failure records an eBay `error` that names the scope.
  - The why for each of these lands in the D4 log.
- **S3 Security.**
  - Session cookies live outside the repo (D5).
  - Listing text from the model goes into form fields as plain text, so prompt-injection impact is low.
  - No new network listener is added: batch is CLI-only.
- **S4 Edge cases.**
  - Double-click on Post: the first create request seen wins, and a second is logged as a warning.
  - Sam edits fields before posting: the recorded URL is right, but the stored price may differ, so record "posted values may differ".
  - An empty batch directory is a usage error (exit 2).
  - A folder with no photos gets an `error` row and the batch continues.
  - `filling` is written under the draft lock before the fill.
  - Browser or window closed by Sam, or a crash: every filled, unresolved tab becomes `unknown`. Only a single tab closed with no submit becomes `not_posted`.
- **S5 Quality.** Keep the per-site script plain code that uses shared fill helpers, with no selector DSL. Keep the adapter seam to an interface with two implementations; no plugin system.
- **S6 Tests.**
  - Unit: the state transitions (the merge and skip rules, including `unknown` over `skipped`), the `mark` transitions, the batch index rebuild, and the mapping fallback.
  - Integration: the Depop fill against a fixture (P3).
  - Live: one real Depop listing.
- **S7 Performance.** One seller's volume. Vision takes about 20 to 40 s per item, which is fine overnight. The open-tab count is P1.
- **S8 Observability.** The D4 log and screenshots. `status --batch` is the dashboard.
- **S9 Deploy.**
  - Lands on main, then a desktop rebuild.
  - Old drafts without per-market fields read as unmapped; `readDraftFile` back-fills them.
  - A leftover `ENABLE_BROWSER_AUTOMATION` in `.env` is ignored.
  - Rollback is `git revert` plus a desktop rebuild; the draft files stay compatible.
- **S10 Trajectory.** Reversibility 4/5. Main debt: the Depop script breaks when Depop changes its form. That is mitigated by the fixture test and errors that name the field. The adapter seam keeps the Partner API, Poshmark and delist sync open.
- **S11 UI.** Small UI scope: `unknown` rows get Mark posted / Mark not posted buttons, and unmapped-field flags show in the publish panel. The deep pass belongs to /plan-design-review.
